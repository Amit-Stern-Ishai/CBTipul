What changed
Removed the custom memory queue, batches, transport, timeouts/backoff, TTL,
delivery acknowledgement requirements, event UUID registry/dedup, capability
blockers, and app-created installation/session analytics IDs. Removed the
Supabase ingestion proposal from current documentation. There is no direct
PostHog HTTP client in the apps. Existing typed events and useful instrumentation
now call only official native SDK capture/reset through a small typed wrapper.
Old app-created analytics identity files are no longer read or written; no
cleanup deletes preferences, Keychain data, patient-name mappings or app data.

Replay off (therefore replay screenshots off); lifecycle/screen/interaction

Supported beforeSend filters unexpected properties and automatic events;
allowed enum/UUID/scalar fields are checked. No in-memory event registry.
The SDK's top-level random anonymous distinct_id, SDK-generated event UUID,

Other SDK context properties are stripped, including device name, screen/

$set/$set_once, exception lists, groups and unlisted context. Generic device
model/version information is supplied explicitly by the typed platform mapper.
No names/emails/phone numbers, notes/diaries/answers/scores/AI text/messages,
notification bodies, clinical/patient record IDs, invitation token/URL, auth/
push token/credentials, request/response body/header or raw errors are allowed.

Network/storage behavior inherent to the SDK
The SDK transports event batches with the public project token, upload sent_at
and ordinary HTTP headers. Network peers can see the connection's source IP;
geoip_disable does not hide it or configure stored-IP removal.
SDK initialization may GET /array/<project token>/config from the EU assets
host even with optional product features disabled. Standard SDK reset may
internally reload /flags as a new anonymous identity despite preload=false;
this is SDK behavior, not a custom feature-flag integration. These infrastructure
requests are not event beforeSend callbacks; they contain SDK/project anonymous
context, not auth/clinical IDs. SDK device ID can be retained across reset for
internal bucketing; the app never supplies a device/hardware identity.
Feature-flag reload transport may include SDK anonymous distinct/device IDs,
empty groups, timezone (iOS), geoip opt-out (iOS), and empty person properties;
no app identify/person/group registration is used. Projects should have no
surveys/replay/autocapture enabled for this manual-event integration.
SDK storage/queues/identity persist according to SDK defaults. iOS uses its
SDK-owned application-support storage; Android uses SDK preferences and cache
queue files. Existing Android allowBackup=false/auth exclusions are preserved.
Device-transfer behavior varies by vendor; SDK-generated anonymous preferences
may follow SDK/platform storage behavior. No custom restore identity is added.
