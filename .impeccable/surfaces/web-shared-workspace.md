# Web shared session workspace — Operate

Scope: therapist-operated Hebrew RTL workspace for sharing the current questionnaire or diary during a session. Preserve the existing web navy, sky-blue and Rubik identity. This surface extends the web patient workspace; it does not establish a new app-wide system. Source authority: web/src/ui/App.tsx and shared.tsx, web/src/workspace/PatientWorkspace.tsx, PatientTimeline.tsx, DiaryFlow.tsx, DiaryWorksheet.tsx and shared-workspace.css.

Entry: the single “התחלת פגישה כעת” action opens /shared/:patientId/questionnaire in the current tab. It opens the shared workspace without creating or saving a session, scheduling an event or starting a timer. The earlier separate share chooser/window is superseded. Questionnaires and all three diaries are available in the shared navigation; sessions and private patient navigation are absent. The selected patient's display name is passed through account-and-patient-matched route state, with “עובדים יחד” as the fallback.

Interaction: shared questionnaires open inline. History is available before opening a record and can be revealed explicitly while working; it recedes while the editor is active. Patient-authored questionnaires are read-only, including disabled answer controls and save. Existing completeness, entitlement, saving, conflict and uncertain-save protections remain. The record status distinguishes read-only, unsaved, saved and historical content; opening a form is not a save.

All three shared diaries offer “תצוגה ממוקדת” and “תצוגה מלאה” over the same mounted worksheet panels and controlled draft. Switching presentation modes preserves the draft and local control state. Focused view provides previous/next, direct section selection, adjustable text size and fullscreen. Moving sections focuses the heading and resets the content pane's scroll. Full view is one large, vertically ordered column, with a focus action for each section. Diary 3 retains its seven-section clinical sequence and visible לפני / בחינה מחדש / אחרי grouping. Fullscreen failure has a readable fallback message.

Visual decisions: compact navy #002B5D header, sky #D0F0FF navigation strip, pale #F4FBFF canvas, white working surfaces and navy #00244E ink. Turquoise #00E3DB with a teal border identifies record creation; selection and focus use existing navy/teal treatments. Local Rubik, labeled navigation and 3px teal focus outlines preserve the web language. Full review uses compact 18px answer text and 16px headings; focused editing retains presentation-scale text. Focused desktop content scrolls in one bounded pane with navigation and save nearby; save is in normal flow. At 850px and below, navigation becomes two columns, controls wrap, side insets become 16px and the focused pane uses normal page scrolling. Full review groups into two columns below 850px and one below 500px. Long content grows rather than being clipped. Alternative-thought focused editing shows the current automatic thoughts as read-only context; overview already shows them in their own column.

Privacy boundary: the shared route owns a separate QueryClient and uses shared patient/record query keys and shared record loading. Directory/name queries and session choices are disabled here; private notes and session assignment are absent. Do not infer that UI hiding alone enforces server permissions. A route-level exit guard remains mounted above authorization, consent, loading and error states. In-app navigation out of /shared/ requires confirmation that private information will appear and asks the therapist to stop screen sharing. Dirty drafts also require confirmation; navigation is blocked while saving. This confirmation does not automatically stop Zoom or control browser/OS screen sharing. Browser unload protection applies to dirty drafts.
